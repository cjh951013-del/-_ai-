# 개발팀

> AI 제품 개발과 기술 인프라 구축을 담당하는 핵심 엔진

---

## 팀 미션

**"빠르고 신뢰할 수 있는 AI 제품을 만든다"**

사용자 문제를 AI 기술로 해결하는 제품을 설계·개발·운영하며, 안정적인 기술 인프라 위에서 빠르게 실험하고 검증합니다.

---

## 핵심 책임 영역

| 영역 | 내용 |
|------|------|
| AI/ML 개발 | LLM 파이프라인, 프롬프트 엔지니어링, 모델 파인튜닝 |
| 백엔드 개발 | API 설계, 서버 아키텍처, 데이터베이스 설계 |
| 프론트엔드 개발 | 사용자 인터페이스, UX 구현, 웹/앱 개발 |
| 인프라 / DevOps | 클라우드 인프라, CI/CD, 모니터링, 보안 |
| 데이터 엔지니어링 | 데이터 파이프라인, 분석 환경, 학습 데이터 관리 |

---

## 기술 스택

### AI / ML
- **LLM**: Claude (Anthropic), GPT-4, 오픈소스 모델 (Llama, Mistral)
- **프레임워크**: LangChain, LlamaIndex
- **벡터 DB**: Pinecone, Weaviate
- **ML Ops**: MLflow, Weights & Biases

### 백엔드
- **언어**: Python, Node.js (TypeScript)
- **프레임워크**: FastAPI, Express
- **DB**: PostgreSQL, Redis, MongoDB
- **메시징**: Kafka, RabbitMQ

### 프론트엔드
- **프레임워크**: Next.js (React), TypeScript
- **스타일**: Tailwind CSS
- **상태 관리**: Zustand, React Query

### 인프라
- **클라우드**: AWS (주력), GCP
- **컨테이너**: Docker, Kubernetes
- **CI/CD**: GitHub Actions
- **모니터링**: Datadog, Sentry

## 개발 프로세스

### 스프린트 사이클 (2주)
```
월요일        수요일          금요일 (다음주)
스프린트 시작  중간 체크인     스프린트 리뷰 & 회고
```

### 데일리 스탠드업
- 매일 오전 10:00 (15분)
- 어제 한 일 / 오늘 할 일 / 블로커

### 코드 리뷰 규칙
- 모든 PR은 최소 1명 이상 승인 필요
- PR 크기: 300줄 이하 권장
- 리뷰 응답 SLA: 24시간 이내

### 브랜치 전략
```
main          ← 프로덕션 배포 브랜치
  └─ dev      ← 개발 통합 브랜치
       └─ feature/[작업명]   ← 기능 개발
       └─ fix/[버그명]       ← 버그 수정
       └─ chore/[작업명]     ← 기타 작업
```

## 코드 품질 기준

- **테스트 커버리지**: 핵심 비즈니스 로직 80% 이상
- **문서화**: 모든 API 엔드포인트 Swagger 문서 필수
- **린팅**: 커밋 전 자동 lint/format 실행 (pre-commit hook)
- **보안**: 비밀키·자격증명 코드에 절대 포함 금지 (`.env` 사용)

## 협업 원칙

1. **문서 우선** — 구두 합의보다 문서화된 결정을 우선합니다.
2. **작게 자주 배포** — 큰 배포보다 작고 빠른 배포를 선호합니다.
3. **장애는 팀의 책임** — 개인 비난 없이 시스템 개선에 집중합니다.
4. **데이터로 판단** — 직관보다 측정 가능한 지표를 기준으로 합니다.
5. **심리적 안전** — 모르는 것을 질문하고 실수를 공유하는 문화를 만듭니다.

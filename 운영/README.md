# 운영팀

> 서비스가 멈추지 않고, 고객이 떠나지 않도록 만드는 팀

---

## 팀 미션

**"고객이 문제를 느끼기 전에 해결하고, 느꼈다면 24시간 안에 해소한다"**

서비스 안정적 운영, 고객 지원, 내부 프로세스 최적화를 통해 비즈니스가 지속적으로 성장할 수 있는 기반을 만듭니다.

---

## 핵심 책임 영역

| 영역 | 내용 |
|------|------|
| 고객 지원 | 문의 응대, 불편 처리, 환불·계약 처리 |
| 서비스 운영 | 장애 모니터링, SLA 관리, 운영 지표 추적 |
| 내부 프로세스 | 업무 자동화, 사내 도구 관리, 프로세스 문서화 |
| 온보딩 관리 | 신규 고객 셋업 지원, 사용 가이드 운영 |
| 데이터 & 리포팅 | 운영 KPI 집계, 주간·월간 보고서 작성 |

---

## 핵심 KPI

| 지표 | 목표 기준 |
|------|----------|
| 고객 문의 응답 시간 (FRT) | 평일 4시간 이내 |
| 문제 해결률 (Resolution Rate) | 95% 이상 |
| 고객 만족도 (CSAT) | 4.5 / 5.0 이상 |
| 서비스 가동률 (Uptime) | 99.9% 이상 |
| 이탈률 (Churn Rate) | 월 2% 이하 |

## 운영 프로세스

### 고객 문의 처리 흐름
```
문의 접수 → 1차 분류 (FAQ 해결 가능 여부)
         → FAQ 해결 가능: 즉시 답변
         → 기술 이슈: 개발팀 에스컬레이션 (Slack #dev-support)
         → 정책 이슈: 운영 리드 확인 후 답변
         → 해결 완료 → CSAT 수집
```

### 장애 대응 프로세스 (Incident Response)
| 단계 | 내용 |
|------|------|
| 감지 | 모니터링 알림 또는 고객 제보 |
| 초기 대응 | 개발팀 즉시 알림, 영향 범위 파악 |
| 고객 공지 | 15분 이내 서비스 상태 페이지 업데이트 |
| 복구 | 개발팀 주도, 운영팀 고객 커뮤니케이션 담당 |
| 사후 리뷰 | 48시간 내 포스트모템 작성 및 공유 |

### 정기 보고
| 보고 | 주기 | 형식 |
|------|------|------|
| 고객 지원 현황 | 매주 월요일 | Slack 요약 + Notion |
| 운영 KPI 리포트 | 매월 첫째 주 | Notion + 전체 공유 |
| 이탈 고객 분석 | 분기별 | 리포트 + 전략 회의 |

| 역할 | 주요 업무 |
|------|----------|
| 운영 리드 | 팀 전략, SLA 관리, 타 팀 조율, 에스컬레이션 결정 |

| 고객 지원 담당 | 1차 문의 응대, FAQ 관리, CSAT 추적 |

---

## 협업 원칙

1. **고객 목소리가 최우선** — 고객 VOC는 즉시 기록하고 관련 팀에 공유합니다.
2. **에스컬레이션을 두려워하지 않는다** — 모르거나 권한 밖의 문제는 빠르게 올립니다.
3. **프로세스를 문서화한다** — 구두로만 전달된 업무 방식은 반드시 Notion에 기록합니다.
4. **데이터로 개선한다** — 반복되는 문의와 불편은 근본 원인을 찾아 제거합니다.
5. **공감이 먼저** — 기술적 해결보다 고객 감정 해소가 먼저입니다.

## 온보딩 체크리스트 (신규 팀원)

- [ ] 고객 지원 툴 계정 설정 (Intercom / Freshdesk)
- [ ] 운영 Slack 채널 입장 (`#운영`, `#고객지원`, `#dev-support`, `#alert`)
- [ ] 서비스 상태 모니터링 대시보드 열람 권한 확인
- [ ] 고객 응대 가이드라인 및 FAQ 문서 숙지 (Notion > 운영팀 > 응대 가이드)
- [ ] 장애 대응 런북 숙지 (Notion > 운영팀 > 런북)
- [ ] 최근 포스트모템 2~3건 리뷰
- [ ] 기존 팀원 섀도잉 — 실제 고객 문의 응대 관찰 (첫 1주)
